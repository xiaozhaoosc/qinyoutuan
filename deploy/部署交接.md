
```bash

cloudflared tunnel delete qyt-fallback      # 会提示删 CNAME
```

## 7. 重建 / 升级（服务器构建，Path 目标为**本机这套**）

> 注意：当前 192.236.223.225 是**旧路径 `/opt/qingzhou` + `qingzhou.service`**。
> 新版 `install.sh` 会装到新路径 `/opt/qinyoutuan` + `qinyoutuan.service`（全新一套、DB 不同，**不会**就地接管旧库）。
> 因此**本机升级请用下面的「服务器构建」就地换二进制**；`install.sh` 仅用于全新机器。

```bash
# 在 192.236.223.225 上（root）
export PATH=/usr/local/go/bin:$PATH
cd /opt/qz-src/frontend && npm ci --no-audit --no-fund && npx vite build
cd /opt/qz-src
go build -trimpath -ldflags "-s -w -X qingzhou/internal/version.Version=<新版本>" -o /opt/qinyoutuan.new .
# 备份 + 替换 + 改配置 + 重启（保留 DB 与 QZ_SECRET_KEY）
cp -a /opt/qingzhou/qingzhou /opt/qingzhou/qingzhou.old.$(date +%Y%m%d%H%M%S)
cp -a /opt/qingzhou/qingzhou.env /opt/qingzhou/qingzhou.env.bak.$(date +%Y%m%d%H%M%S)
install -m 755 /opt/qinyoutuan.new /opt/qingzhou/qingzhou
# 如需切对外地址/更新仓库：sed 改 /opt/qingzhou/qingzhou.env 后再重启
systemctl daemon-reload && systemctl restart qingzhou
curl -s http://127.0.0.1:8086/api/health   # 期望返回新版本
```

服务器已装工具链：Node v20.19.2 / npm 9.2 / Go 1.25.5（`/usr/local/go/bin`）/ cloudflared。构建源码目录 `/opt/qz-src`，新二进制副本 `/opt/qinyoutuan.new`。

**走 fork release 的一键安装（新机器）**：
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/xiaozhaoosc/qinyoutuan/main/install.sh)
```

## 8. 发布新版本流程（GitHub）

1. 在 fork 推送 `dev` 的改动。
2. 打 tag 并推送：`git tag vX.Y.Z && git push xiaozhaoosc vX.Y.Z`
3. GitHub 网页创建该 tag 的 Release（或 API），触发 `release.yml`（产物）+ `docker.yml`（镜像）→ 均成功后再更新线上（见 §7）。
4. 产物名 `qinyoutuan-linux-*`；镜像 `ghcr.io/xiaozhaoosc/qinyoutuan:vX.Y.Z`。

## 10. 关键告警 / 铁律

- **`QZ_SECRET_KEY` 与 `QZ_DB` 永不改/不删**，否则用户数据丢失、加密内容解不开。
- 阅读 env 时对密码类脱敏；本机密钥都在 `~/.ssh/`（面板密码 `id_rsa_panel`、GitHub 令牌 `gh_panel_token`），均不入库。
- OS 无防火墙 → 谁开放端口由 **provider 安全组**决定，改端口记得同步安全组。
- 在线更新、一键安装都指向 fork（`xiaozhaoosc/qinyoutuan`）；离开 fork 自用需相应改 `QZ_UPDATE_REPO` / `QZ_REPO`。
