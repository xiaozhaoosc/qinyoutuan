## 2. 已修复问题明细（根因 → 修复 → 验证）

### 2.1 Argo 隧道回源失败（订阅里 argo 节点全 timeout/error）

- **现象**：cloudflared 日志满屏 `Unable to reach the origin service ... EOF`；面板 `curl https://<trycloudflare>/ws` 502。
- **根因**（两条叠加）：
  1. **回源目标错误**：`ArgoSpec.TargetPort = ib.ListenPort`，cloudflared 明文 HTTP 回源到 **Reality(TLS)** 入站，sing-box 只接受 TLS 握手 → 秒断 EOF。设计文档要求"为 argo 入站派生无 TLS 明文 ws 回源入站"，移植实现漏掉。
  2. **temporary 13 端口错配**：quick tunnel 只服务 443(80)，其余 12 个 CDN 端口必超时。
- **修复**（`ea0f6fe`）：
  - `internal/sbproc/cloudflared.go`：新增 `ArgoOriginPortDelta = 10000`。
  - `internal/store/singbox.go`：新增 `argoOriginInbound`，为 argo 入站派生无 TLS 明文 ws 回源入站（`127.0.0.1:<ListenPort+10000>`，同 users/path）；`argoSpec()` 回源指向派生端口；`argoVariantLinks` 按 `mode` 区分（temporary 只发 443，fixed 才 13 端口）。
  - `main.go` / `internal/api/argo_remote.go`：同步回源端口偏移。
- **验证**：sing-box config 新增 `30086` 回源入站；cloudflared 单元 `--url http://127.0.0.1:30086`；日志无 EOF；订阅只剩 1 个 argo-443 节点；sing-box 客户端经 argo-443 访问 gstatic 返回 **204**。

### 2.2 直连节点连不上（客户端 Clash/Mihomo）

- **现象**：刷新/重新导入订阅后直连节点仍不通；服务端 e2e 却 204。
- **排查链**：
  1. 本机 openssl 连 `64.181.244.178:20086` TLSv1.3 正常、返回微软证书 → **网络与服务端 Reality 正常**。
  2. 订阅 singbox 格式直连节点缺 `reality` 块 → 根因 A。
  3. Clash 格式直连节点缺 `reality-opts` → 根因 B。
  4. **根因 C（最终）**：Mihomo（Clash 内核）对 **vmess+Reality 组合支持不完整**，协议换成 vless 后兼容。
- **修复**（`3a677f3` `cb89e2d` `f2ed0f4`）：
  - `internal/singbox/link.go`：vmess 链接 JSON 补 `security=reality/pbk/sid`；argo 变体清空 Reality（CF 边缘终结 TLS）。
  - `internal/subconv/singbox.go`：vmess 渲染透传 `security=reality`，pbk/sid 改用 `tlsParam` 读取（vmess 链接的键在 JSON payload）。
  - `internal/subconv/clash.go`：vmess 分支补 `reality-opts`。
  - **生产入站协议 `vmess` → `vless`**（DB `UPDATE sb_inbounds SET type='vless'`）；`argoOriginInbound`/argo 变体/`sb_admin.go` 校验支持 vless。
- **验证**：sing-box config 20086/30086 均为 `type: vless`；clash 订阅直连节点 `type: vless` + `reality-opts`；vless+Reality 直连 e2e **204**。

### 2.3 20086 端口公网不通

- **根因**：服务器 iptables 仅放行 `80/8081/22`，20086 被兜底 REJECT。
- **修复**：`iptables -I INPUT 1 -p tcp --dport 20086 -j ACCEPT`，`iptables-save > /etc/iptables/rules.v4` 持久化。
- **验证**：`Test-NetConnection 64.181.244.178:20086` → True。

### 2.4 TestRFC5987Escape

- **根因**：期望值还是旧品牌"轻舟"的 UTF-8 编码。
- **修复**：改为"亲友团" `%E4%BA%B2%E5%8F%8B%E5%9B%A2`（`178467b`）。

## 4. 固定隧道（fixed）配置方案

**目标**：13 端口全通 + 稳定域名 + 隐藏真实 IP。

**token 获取**（Cloudflare 控制台）：
1. 注册/登录 dash.cloudflare.com → 添加域名 `myservs.rouroujuxuan.top`（DNS 托管给 CF：aliyun 解析里把 NS 改为 CF 提供的两个 NS）。
2. **Zero Trust → Networks → Tunnels → Create a tunnel**（Named tunnel）→ 创建后复制 **token**（`eyJ...` JWT）。
3. 该 Tunnel 配置 **Public Hostname**：`sub.myservs.rouroujuxuan.top` → Service `http://127.0.0.1:30086`（**必须 30086 回源端口**，非 20086）。
4. 面板"入站 → Argo 隧道"：模式选**固定**，填 token + 域名 `sub.myservs.rouroujuxuan.top`。

> 语义：`temporary` = 1 端口(443)，`fixed` = 13 端口（代码红线）。
